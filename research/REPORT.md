## 2. ルックアヘッド対策

| 項目 | 扱い |

## 3. 期間分割

| 段階 | 学習（探索） | 検証 | 役割 |
|---|---|---|---|
| A | 7/15〜7/31 | 8月 | ルールを選ぶ（ここで固定） |
| B | 7/15〜8/31 | 9月 | 固定したルールを1回だけ評価 |

- 本報告の「検証期間」は、8月（段階A）と9月（段階B）の合算。どちらもモデルの学習外。
- ルールは段階Aの成績だけで、次の基準で機械的に選んだ: 対象100R以上、的中率が一定以上、その中で8月の回収率が最大。

## 4. 手法

1. **馬複確率モデル**: 各馬の強さを、T-5の単勝・複勝オッズから計算した確率と、AI NAVIのfairWin/fairPlaceから計算した確率の対数を足し合わせて表す。この強さで1・2着が決まるモデル（Plackett-Luce、2着の確率は係数λで補正）を学習期間で最尤推定し、全組の確率 `pm` を出す。
   - 学習した係数（7〜8月）: 単勝市場0.65、複勝市場0.50、AI単勝0.03、AI複勝0.38、λ=0.73
2. **レース選択**: 上位k組の `pm` 合計（その券種の推定的中率）が閾値c以上のレースだけ買う。
3. **馬（組）選択**: `pm` の上位k組を買う。
4. 比較対象:
   - 市場（単勝のみ）
   - 市場（単勝＋複勝）
   - AI NAVIだけのASTRA型（B01・B04・B05）

## 6. 採用／不採用と理由

| 条件 | 判定 | 理由 |
|---|---|---|
| **R2**（上位2組の合計≥45% → 2点） | **SHADOW採用（記録を継続）** | 検証期間の2期間とも的中率56〜60%、回収率78〜84%で安定。高配当への依存もない（最高払戻を除いて79%）。ASTRA型より的中率・回収率とも高い。ただし100%未満なので、利益目的の購入には採用しない |
| R1（上位1組≥30% → 1点） | 不採用（参考） | 回収率はR2より低く、的中率も約41%。最大連敗10R・週別のブレが最大 |
| R3（上位5組≥60% → 5点） | 不採用（参考） | 的中率は74%で最も高いが、回収率は75%。点数が多く、損失の絶対額（ドローダウン約12万円）が大きい |
| 期待値型（期待値≥θ、最低確率、最大9点、180条件） | 不採用 | 9月に100%超は1件（23R）だけで、全体の中央値は58%。モデル確率÷市場確率が大きい組ほど確率を高く見積もりすぎており、実際の的中率は市場の値に近い。配当も推定より30〜40%低い |
| 期待値型のうち8月最良（5点・比1.3・合計60%） | 不採用 | 8月は82%だが、的中率8.5%の穴依存。9月は75%に低下 |
| 少数レースで高回収率（例: 9月16R 回収率196%） | 不採用 | 8月の同じ条件は29Rで39%。再現せず、件数も不足 |
| steam（T-10→T-3で売れている馬を追う） | 不採用 | 市場の値を入れた後では有意な効果なし（1着予測でz=-1.2） |
| 組単位のsteam（T-5→T-3のシェア増） | 不採用 | 7〜8月と9月で結果が逆になり、再現しない |
| 場別の選別 | 不採用 | 1場あたり6〜56Rで判断できない。見た後で選ぶと過学習になる |

## 7. ChatGPT（Astra/Sol）検証の再検証

参考仮説として扱い、本データで確認し直した。

| ChatGPT側の主張・仮説 | 本データでの再検証 | 判定 |
|---|---|---|
| B01（期待値上位3×複勝上位3）は全期間63.3%で採用不可 | 8月64.2%、9月61.4% | 一致（不採用） |
| B05（複勝上位4頭BOX）は的中率56%・回収率75%前後 | 8月56.7%/71.9%、9月56.0%/74.2% | 一致 |
| 場別の選別は過学習で採用不可 | R2を場別に見ても件数不足 | 一致 |
| 次の仮説: 馬複の同時確率を校正し、購入時点の組価格と比べて利益余地のある券だけ買う | T-5の組価格を推定して検証した。9月に100%超は180条件中1件（23R） | **否定**（価格推定の誤差と直前資金で、見かけの価値が消える） |
| MARKET_REJECT（直前に売れなくなる候補を見送る） | 馬複には直接対応しない。T-10→T-3の人気低下は、市場の値を入れた後では予測力なし | 馬複では効果なし（複勝候補の見送りは未検証） |
| 3頭/5頭Cluster（8月 ROI 131%/122%） | M3Q等の特徴量が今回のデータにない | 未検証 |
| 「期待値→穴軸、複勝順位→相手」の役割分担 | AIの寄与は複勝側（fairPlace）で、期待値型の穴狙いは不採用 | 部分的に支持（複勝側が主） |

## 8. 運用（SHADOW記録）

- `predict.py`（パラメータは `params_v1.json` に固定、7〜8月で学習）に、当日のAI NAVI JSONとT-5のsnapshots.csvを渡すと、R1〜R3の買い目を出す。9/27分でバックテストと完全に同じ買い目になることを確認済み。
- 10月以降、**パラメータもルールも変えずに**R2を記録する。100R以上たまった時点で、的中率・回収率・最大連敗・週別のブレを再評価する。
- 既存のNote-Hidden、HW-SAC、Place-Steam、ファイナルAは変更しない。本研究とは混ぜて集計しない。

## 9. 回収率100%を狙うための追加データ（優先順）

1. **T-1〜T-0（締切直前）のオッズ**: 直前の資金による配当低下（約13%）を、どこまで避けられるか測る。
2. **T-5時点の馬複全組オッズ**: 価格推定の誤差（対数sd 0.43）をなくし、期待値型を正しく再検証する。
3. **期間の延長（4〜6月、10月以降）**: AIの上積みを、場・クラス別に安定して推定する。

## 10. 再現手順

```
S=<作業フォルダ>   # S/raw: 指数JSON, S/ts: 時系列(日付フォルダ), S/csv: NAR CSV
python3 research/prepare.py $S
python3 research/pairs.py $S
python3 research/walk.py $S        # 段階A/Bの採点と期待値型180条件
python3 research/frontier.py $S    # 的中重視型の比較

```
